# Rejection — Attempted / Intended vs Realized Event

Date: 2026-09-01  
Verdict: **KILL-NOVELTY**

## Natural question

Does a model distinguish an event that someone tried or intended to make happen from an event that actually occurred?

## Semantic aliases

- attempt vs success
- intended vs realized event
- implicative predicates
- actuality entailment
- event factuality

## Why it looked promising

The distinction is ordinary and can hold event content fixed while varying whether realization is licensed. It looked like a simple event-status latent object.

## Decisive kill evidence

The proposed object collapses into the mature event-factuality / implicativity literature. MAVEN-FACT provides large-scale event factuality annotations and explicitly evaluates LLMs on whether events are factual, possible, or impossible. ACL 2026 `From Factuality to Meta-Factivity` explicitly pushes event factuality from black-box prediction toward white-box/internal analysis. Classical implicative constructions such as `manage`, `fail`, and `try` are lexical windows on this already-owned actuality-status object.

Thus an `attempted/intended versus realized` direction would primarily mechanize an established event-factuality distinction rather than introduce a new scientific object.

## Strongest-neighbor warning

Do not revive as attempt/success vector, implicative circuit, actuality-entailment steering, or `try/manage/fail` activation patching.

## Death code

`F2 / N0-N2 — direct event-factuality object ownership; lexical-window change is not a concept-level delta.`

## Resurrection condition

Only a different natural event property that cannot be reduced to factuality, possibility, actuality entailment, or culmination could reopen this family.
