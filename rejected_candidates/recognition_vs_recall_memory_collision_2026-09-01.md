# Rejection — Recognition vs Recall

Date: 2026-09-01  
Verdict: **KILL-NOVELTY**

## Natural question

Can a model recognize information as familiar even when it cannot actively recall that information from a cue?

## Semantic aliases

- recognition memory vs recall
- availability vs accessibility
- cued recall
- retrieval bottleneck

## Why it looked promising

The distinction is simple, classical, and naturally relevant to whether knowledge is stored but inaccessible. It offers clean behavioral dissociations and an obvious causal retrieval question.

## Decisive kill evidence

Orhan (2023) directly studies recognition, recall, and retention of few-shot memories in LLMs. CoNLL 2026 explicitly compares transformer item-recognition and cued-recall behavior. August-2026 factuality work further frames parametric factual failures as a recall bottleneck despite encoded information.

Therefore recognition-vs-recall and storage-vs-retrieval accessibility are already explicit LLM scientific objects. Adding causal patching would mostly mechanize the same distinction.

## Strongest-neighbor warning

Do not revive as stored-but-not-recalled, recognition direction, accessibility vector, or recall-bottleneck circuit without an independent new object.

## Death code

`F2 / N0-N2 — direct object ownership across multiple LLM memory lines.`

## Resurrection condition

Only a distinct memory distinction with its own natural cross-cells and scientific interpretation could reopen this family.
